<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Compose host -> containers | Local operator controls env, volumes, ports, and service selection. |
| CI runner -> service containers | Ephemeral database and Redis are used for automated verification. |
| `.env.example` -> runtime settings | Documented configuration crosses into provider, auth, and database behavior. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-01-03 | Spoofing | Compose service authority | high | mitigate | Product-neutral names, one project/volume, health-gated startup, and Gate 0 assertions prevent a second backend from becoming active. |
| T-01-04 | Information Disclosure | env and CI configuration | high | mitigate | Keep secrets empty in examples, server-only in settings, and assert no real provider key is required by mock CI. |
| T-01-05 | Denial of Service | readiness/startup | medium | mitigate | Separate cheap liveness from dependency readiness and use bounded health retries/Make wait loops. |
| T-01-SC | Tampering | CI dependencies and images | high | mitigate | No new package install is planned; preserve pinned existing images/actions and run non-blocking audits already present. |
</threat_model>
