<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Seed snapshot -> canonical database | Untrusted or stale source rows become queryable facts. |
| Request coarse origin -> PostGIS query | Client-supplied geography and radius influence nearby results. |
| Docker image/init -> database extensions | Image and initialization determine vector/text/spatial capabilities. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-02-01 | Tampering | Alembic lineage and schema | high | mitigate | One `0003` child of `0002`, one-head test, clean upgrade, and ORM/live-schema checks. |
| T-02-02 | Information Disclosure | beneficiary origin handling | high | mitigate | No home-coordinate column; coarse origin input only; explicit privacy tests. |
| T-02-03 | Spoofing | centre verification metadata | high | mitigate | Coordinate status, source record identity, freshness, and verified/synthetic distinction gate nearby claims. |
| T-02-04 | Denial of Service | spatial/radius query | medium | mitigate | Database GiST index, bounded radius validation, and `ST_DWithin` before distance ordering. |
| T-02-SC | Tampering | database image and extension supply chain | high | mitigate | Pin the image/build inputs and verify extension versions in CI; no second database or unreviewed runtime package. |
</threat_model>
