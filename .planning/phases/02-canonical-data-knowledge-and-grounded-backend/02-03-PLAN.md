<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Informal user text -> lexical/vector retrieval | Untrusted text can influence candidate ranking and query syntax. |
| Retrieval candidates -> grounded response | Candidate IDs could be fabricated, stale, synthetic, or mismatched with canonical rows. |
| Coarse origin/radius -> PostGIS result | Client parameters can attempt broad or misleading proximity claims. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-02-09 | Injection | tsquery construction | high | mitigate | Keep token extraction/length bounds and parameterized `to_tsquery`; test operator characters. |
| T-02-10 | Tampering | semantic candidate authorization | high | mitigate | Resolve every candidate ID through canonical SQL and reject nonexistent/mismatched QPs. |
| T-02-11 | Information Disclosure | spatial origin/result payload | high | mitigate | Coarse origin only, bounded radius, no home point persistence, and no distance for stale/missing geometry. |
| T-02-12 | Integrity | embedding backend mismatch | medium | mitigate | Store backend/dimension metadata and hard-fail mixed vector spaces. |
| T-02-SC | Tampering | retrieval/model artifacts | high | mitigate | Use committed embeddings/snapshots, deterministic hashing in mock mode, and no runtime government/provider fetch. |
</threat_model>
