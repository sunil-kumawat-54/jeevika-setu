# docs/decisions.md — AVSAR implementation decision log

Every entry records a choice the dossier did not fully specify, or a conflict
between dossier files that had to be resolved. Source-of-truth priority is
**PLAN.md > ARCHITECTURE.md > TECH_STACK.md > research.md**.

Legend:
- **GAP** — the dossier is silent; simplest compatible implementation chosen.
- **CONFLICT** — two dossier files disagreed; higher-priority file won.
- **DEVIATION** — reality (an unavailable dependency/environment) forced a
  documented fallback.

---

## Gate 0 — scaffold + infrastructure

### D-001 (GAP) Python package root is `services/`, package name is `core`

ARCHITECTURE.md §1 fixes the directory as `services/core/...`, and RULE 4 pins
the module path `services/core/domain/scheme_constants.py`. The dossier never
names the import path. Chosen: `services/` is the source root and `core` is the
package, so imports read `from core.domain.scheme_constants import ...`.
`PYTHONPATH=/srv/services` in the container, `pythonpath = ["services", "."]`
in `pyproject.toml` for pytest.

### D-002 (GAP) Container layout and the repo bind-mount

`services/core/Dockerfile` builds a self-contained image (`COPY services data
seeds scripts pipelines`), and `infra/docker-compose.yml` additionally
bind-mounts the whole repository at `/srv`. Two reasons: `make ingest` writes
`seeds/*.json` straight back into git (RULE 3 requires seeds to be committed),
and the Gate-0 layout tests assert the ARCHITECTURE §1 tree from inside the
container. The image works standalone without the mount.

### D-003 (GAP) `make` targets run inside the `core` container

TECH_STACK §7 lists the targets but not where they execute. All Python targets
run as `docker compose exec -T -w /srv core …` so a judge needs only Docker —
no host Python environment, no host virtualenv. `make dev` is the one
exception: it is explicitly the host hot-reload path (`uvicorn --reload` +
`next dev`).

### D-004 (DEVIATION) Windows/Git-Bash path mangling

MSYS rewrites container-absolute arguments such as `/srv/scripts/x.py` into
`C:/Program Files/Git/srv/...`. The Makefile therefore exports
`MSYS_NO_PATHCONV=1` / `MSYS2_ARG_CONV_EXCL=*` and passes **container-relative**
paths under `WORKDIR /srv`. No effect on Linux/macOS.

### D-005 (DEVIATION) GNU Make was absent from the build machine

`make` is not part of Git for Windows. Installed GNU Make 4.4.1 via
`winget install ezwinports.make`. Recorded in `docs/runbook.md` as a Windows
prerequisite; Linux/macOS ship make already.

### D-006 (CONFLICT→resolved) Next.js patch version

TECH_STACK §4 pins `next@14.2.*`. `npm install` resolved to 14.2.18, which npm
flags with a known security advisory (Next.js security update 2025-12-11).
Pinned **14.2.35** — the newest patch inside the mandated `14.2.*` range, so the
TECH_STACK constraint is preserved and the advisory is cleared.

### D-007 (GAP) Postgres image and extensions

TECH_STACK §1 requires "PostgreSQL 16 + pgvector 0.7+". Chosen image
`pgvector/pgvector:pg16` (ships PostgreSQL 16.15 + pgvector 0.8.6).
`infra/db/init.sql` also enables `pg_trgm`, used for the fuzzy `qp_code ↔ name`
join in pipeline 03 and for crosswalk phrase lookup.

### D-008 (GAP) Web healthcheck endpoint

docker-compose needs a liveness probe for `web`. Added
`apps/web/app/api/health/route.ts` returning `{status:"ok"}`. It is a probe
only; it is not part of the BFF proxy surface.

### D-009 (GAP) `/metrics` lives on core, in Prometheus text format

ARCHITECTURE §10 asks for `/metrics` "(Prometheus-format)" without naming a
library. Implemented in-process in `services/core/metrics.py` (no
`prometheus_client` dependency): counters plus per-stage p50/p95 histogrampoints
required by TECH_STACK §8.

### D-010 (GAP) Error contract is a shared table, not per-router strings

ARCHITECTURE §5 requires `{code, human_{lang}, retryable}` and RULE 7 requires
every error to be speakable in the active session language. All messages live in
`services/core/errors.py` as one `code → {lang: sentence}` table for hi/mr/te/en,
surfaced via `AvsarError`.

### D-011 (GAP) Four UI languages, not three

PLAN.md §3 names hi/mr/te for the voice flow; ARCHITECTURE §1 names
`data/prompts/dialogue.{hi,mr,te,en}.json`. English is included as a fourth
language because the higher-priority file's file-list demands it and the build
prompt lists `hi mr te en`. Language selection therefore shows 4 options — the
maximum allowed by RULE 7.

## Gate 1 — data layer

### D-012 (GAP) Surrogate integer primary keys, UUID session ids

ARCHITECTURE §4 writes `id PK` without a type. Chosen: `BIGINT GENERATED BY
DEFAULT AS IDENTITY` for every table, except `sessions.id`, which is a UUID —
session ids travel in URLs (`/sessions/{id}/turn`) and must not be guessable or
enumerable.

### D-013 (GAP) `districts` seed source and code format

ARCHITECTURE §4 says "Census 2011 LGD-style codes (state+district); a static
`districts(code,name_hi,name_en)` seed ships in-repo". Implemented as
`seeds/districts.json` with a 7-character code `SSDDD`-style key
(`state_code` + `district_code`) plus `name_en`, `name_hi`, `name_mr`,
`name_te`, and `state_name`. Marathi/Telugu names are additional columns beyond
the ARCHITECTURE minimum because the beneficiary UI must render the district in
the session language.

### D-014 (GAP) `nsqf_level NUMERIC(3,1)` enforcement

RULE 5 forbids integer casts anywhere in filtering/eligibility/scoring/joins.
Enforced three ways: the column type, a `CHECK (nsqf_level >= 1 AND nsqf_level
<= 10)` constraint, and `services/core/tests/test_gate1_models.py` which asserts
that half-levels survive a write/read round-trip and that the recommender's
comparisons stay in `Decimal`/`float`.

## Gate 2 — ingestion + seeds

_(entries appended as the gate lands; the authoritative fallback narrative for
external sources lives in `docs/ingest-report.md`)_

### D-015 (DEVIATION) PM-AJAY portal unavailable during the whole build

`pmajay.dosje.gov.in` serves `resources/views/maintenance.blade.php` on every
HTML route, `POST /front/reportajax` returns HTTP 500 with the Laravel
debug-mode stack trace research.md §3.4 warned about, and the host ships an
**incomplete TLS chain** (Windows succeeds via AIA fetching; OpenSSL — i.e. every
Linux container — fails with `CERTIFICATE_VERIFY_FAILED`). Static assets on the
same host still serve, which is why pipeline 06 still builds a real RAG corpus
from the guidelines PDF.

Consequences, all recorded in `docs/ingest-report.md`:
- `courses` is a documented fallback of **1,135 rows**, not the ≥2,000 the gate
  prefers. QP code, job-role name, sector and NSQF level are **real** NCVET
  values; only catalogue membership and the Course/Sub-Course grouping are
  synthesised, and every row carries `synthetic=true`.
- The catalogue was **not** padded with invented rows to reach 2,000. Fictional
  courses would enter the candidate pool and could be recommended to a
  beneficiary, which defeats the purpose of a grounded recommender.
- `PMAJAY_INSECURE_TLS=true` exists as an explicit, ingestion-only opt-in for
  operators who accept the risk of the portal's broken chain. It is never
  consulted at runtime.

### D-016 (GAP) Pipeline execution order is 00 → 02 → 01 → 03 → 05 → 06 → 07

PLAN.md §5.1 numbers the pipelines but does not fix an execution order.
Pipeline 01's fallback derives its catalogue from the NCVET register, so 02 runs
first. When the portal is reachable, 01 ignores that seed and the order is
irrelevant.

### D-017 (GAP) Embedding backend selection and the `WITH_ML` build arg

TECH_STACK §1 mandates multilingual-e5-base. The model is **baked into the core
image** (`WITH_ML=1`, default) so the *build* needs network — as every docker
build does — while the *running container* needs none, satisfying RULE 1.
`WITH_ML=0` produces a small image that falls back to a deterministic hashing
embedder; the backend name is stamped on every stored vector and
`assert_compatible()` refuses to compare vectors from different backends rather
than silently returning nonsense.

### D-018 (GAP) QP descriptions carry curated multilingual aliases

PLAN.md §6 STEP 2 defines C2 as top-k over `qp_description_embeddings` but does
not define the description text. Measured: with English-only text, the query
"मैं सिलाई का काम सीखना चाहती हूँ" retrieved *Bijli mistry* and *Safai Mitra*
ahead of any sewing QP. Folding the curated hi/mr/te/en phrases into each QP's
indexed text fixed it (Sewing Machine Operator, 0.8173). This changes what a
description *says*, not how C2 is computed.

### D-019 (GAP) Declared crosswalk gaps, and refusal instead of a near miss

The dossier does not say what to do when a recognised aspiration has no QP in
the register. A crosswalk entry may carry `qp_codes: []` **only** with a
mandatory `gap_reason`; the recommender then refuses and flags officer handoff.
`poultry` is the live case — zero poultry qualifications exist in the ingested
register. Mapping it to "Goat and Sheep Farmer" would have produced a confident
wrong-trade recommendation. The gap also feeds the dashboard gap panel
(PLAN.md §4.2), so the limitation surfaces as the signal an officer needs.

### D-020 (GAP) Relevance floor on C2 candidates

PLAN.md §6 STEP 2 fixes top-k(40) but no similarity cut-off. multilingual-e5
compresses all cosines into a ~0.04-wide band, so min-max normalisation inflated
the 40th neighbour's `semantic_fit`; combined with the mandated 0.25
`local_supply` weight, "Soil Testing Junior Technician" outranked "Sewing Machine
Operator" for the query "सिलाई" purely because it had local seats. C2-only
candidates must now sit within 0.015 cosine of the best hit (margin widens if
that would leave fewer than three). **The STEP 4 weights were not altered** —
the fix belongs in candidate generation, not in the scoring the brief pins.

### D-021 (GAP) Curated candidates are floored at the best observed similarity

A human bound the phrase to the QP, so a C1 hit is the highest-confidence signal
available. If the vector index happens not to return it, it must not score zero
on `semantic_fit` and lose to a loose neighbour — that would invert the point of
building the crosswalk.

### D-022 (CONFLICT→resolved) `districts` seed is wider than ARCHITECTURE §4

ARCHITECTURE §4 specifies `districts(code, name_hi, name_en)`. The real LGD
dataset leaves many `district_name_local` values in Latin script, so populating
`name_hi` from it unconditionally would assert a Hindi name that is not Hindi.
The table therefore also carries `name_local`, `name_mr`, `name_te` and the
Census-2011 codes, and a language-specific name is only claimed when the script
matches. The ARCHITECTURE columns all exist; the addition is strictly additive.

### D-023 (GAP) Synthetic centre_supply is stratified by curated trade

Sampling the catalogue uniformly left Latur — the scripted demo district — with
no tailoring seats, which is both a poor model of a real district and enough to
let an unrelated course outrank the right one. Demo districts now stock ~75% of
the curated trades plus a random tail. Coverage stays deliberately partial so
the gap panel has genuine district-level gaps, and every row remains
`synthetic=true`.

### D-024 (GAP) `doc_chunks` identity key

`UNIQUE (source, page, section, chunk)` silently admitted duplicates because
`section` is nullable and Postgres treats NULLs as distinct — a 244-row corpus
grew to 251 on the second `make seed`. Migration `0002_doc_chunk_identity` adds
stored generated columns `section_key = COALESCE(section,'')` and
`chunk_sha = md5(chunk)`; the digest also avoids overflowing a btree entry once
a ~2,000-character chunk is Devanagari or Telugu.

## Gate 5 — speech router

### D-025 (GAP) Provider preference order, and what counts as "degraded"

TECH_STACK §4 names the ladder but not its order at runtime. Chosen: the
configured `VOICE_PROVIDER` first, then the remaining providers in a fixed
order, with `mock` last so it is always reachable. Any answer served by a rung
*below* the configured primary sets `degraded=true` on the result, the session
row and `/readyz` — including a mock answer in a keyed deployment. Degradation
is therefore visible rather than silent, which is what makes the kill drill
demonstrable instead of merely survivable.

### D-026 (GAP) Demotion is per-provider and time-boxed, not permanent

`PROVIDER_DEMOTE_AFTER=2` consecutive failures demotes a provider; it is then
skipped entirely, so a revoked key costs at most two timeouts per window rather
than two per turn. Demotion decays, so a provider that recovers is retried
without a restart. Verified by `scripts/drill_provider.py`: it asserts the
provider is *not* demoted after one failure, *is* after two, and receives zero
further calls on turn three.

### D-027 (DEVIATION) `x or default` silently discarded deliberate zeros

Four speech adapters and the router normalised optional numbers with
`value or default`, which rewrites a legitimate `0.0` confidence — the exact
signal an empty-audio turn produces — into the default. Replaced with explicit
`if value is None` checks. The bug was found by a test asserting that two empty
ASR results in a row escalate to the tap fallback (`EMPTY_ASR_LIMIT=2`), which
could never fire while zeros were being rewritten.

## Gate 6 — sessions API, auth, RBAC

### D-028 (GAP) SSE event order is a contract, enforced by buffering

ARCHITECTURE §3 draws `transcript → state → recs → tts`, but the natural
implementation emits `recs` as soon as the recommender returns, which is before
the FSM's new `state`. A client that renders on `recs` would then paint cards
for a step it does not yet believe it is on. `recs` and `error` are buffered and
flushed immediately after `state`, so the wire order always matches the drawn
contract. Tested per event, not merely for presence.

### D-029 (GAP) Consent is enforced in the writer, not only in the FSM

RULE 6 requires consent *before* profile slots are persisted. The FSM already
refuses to advance past `consent`, but the FSM is pure logic and a future
caller could bypass it. The session writer independently refuses to write any
slot column while `session.consent_id` is NULL. Two independent guards for a
rule that cannot be allowed to fail once.

### D-030 (GAP) Auth parameters

argon2id with `time_cost=2, memory_cost=64 MiB, parallelism=2` (the argon2-cffi
recommendation for an interactive login on a small VPS); JWT access token 30
minutes, refresh 12 hours — long enough that a finale demo never re-logs-in,
short enough to be defensible. Roles form a strict ladder
`viewer < officer < admin`, so `require_officer` admits admins without
enumerating roles at every endpoint.

### D-031 (DEVIATION) Circular foreign key between `sessions` and `consents`

`sessions.consent_id → consents.id` and `consents.session_id → sessions.id` are
both in ARCHITECTURE §4, which SQLAlchemy cannot order into two `CREATE TABLE`s.
Resolved with `use_alter=True, name="fk_sessions_consent"`, emitting the
constraint as a post-create `ALTER`. The cycle also has to be broken explicitly
before deletion — see `scripts/purge_old.py`, which nulls `consent_id` first.

## Gate 7 — verbalizer, guardrails, RAG

### D-032 (GAP) Which numerals a verbalized answer may contain

RULE 2 says every numeral must come from the tool JSON. Taken literally, that
forbids an ordinary list marker. Chosen: numerals `0,1,2,3` are always allowed
(they can only be ranks — at most three recommendations are returned), and every
other numeral must appear in the tool payload. Devanagari and Telugu digits are
transliterated to ASCII before comparison via `unicodedata.decimal`, so a Hindi
answer cannot smuggle a number past the check by writing it in its own script.

### D-033 (GAP) Failure ladder when the model produces an ungrounded number

`MAX_ATTEMPTS=2`: the first attempt, then exactly one regeneration whose prompt
names the offending numbers back to the model, then the deterministic template.
The template rung needs no model at all, which is why the offline drill can
verbalize with every network call blocked. A grounding failure therefore
degrades to a correct answer, never to a wrong one.

### D-034 (GAP) Hybrid retrieval fusion and injection safety

Reciprocal Rank Fusion with `k=60` over BM25 ∪ pgvector (the value TECH_STACK
§6 cites). The tsquery is built by extracting tokens and joining them
programmatically rather than interpolating user text, so a spoken aspiration
cannot become tsquery syntax. If pgvector or the embedder is unavailable, the
search degrades to lexical-only rather than failing.

### D-035 (GAP) `verify_grounding.py` checks names and QP codes, not only numerals

RULE 2 as written is a numeral check, which a hallucinated course name with no
digits would pass. The script additionally asserts every spoken course name and
QP code appears in the tool JSON, and mixes curated crosswalk phrases with
free-text aspirations that are deliberately *not* curated, so the semantic path
is exercised rather than only the lookup table.

## Gate 8 — beneficiary PWA

### D-036 (DEVIATION) `html lang` did not follow the session language

The layout sets `lang` once at render. A session switched to Telugu therefore
kept `lang="hi"`, which tells a screen reader to pronounce Telugu with Hindi
phonology — a real accessibility defect, not a cosmetic one. `StartClient`
syncs `document.documentElement.lang` on every language change.

### D-037 (DEVIATION) Service worker was cache-first for HTML

research.md §9.5 warns precisely about this: a cache-first HTML shell serves a
stale app after a redeploy, and at a venue that means demoing yesterday's build.
Rewritten to cache-first **only** for revisioned assets (`/_next/static/`, the
manifest, icons) and network-first with a 3 s timeout for HTML and API, with the
cache as the offline fallback. The cache version is bumped so the old strategy
is evicted on first load.

### D-038 (GAP) Audio is normalised in the browser, not the server

`MediaRecorder` output is downmixed and resampled to 16 kHz mono PCM WAV via
`OfflineAudioContext` before upload, capped at 15 s. Every provider in the
ladder wants 16 kHz mono, so converting once on the client keeps the server
adapters thin and the upload small on a village connection.

## Gate 9 — officer dashboard and exports

### D-039 (DEVIATION) `live_check` moved out of `admin.py`

The RULE 3 test greps the runtime for government hostnames and found the PM-AJAY
host inside the admin router. The check itself is legitimate — RULE 3 permits
*one* explicitly labelled live-check endpoint — but burying it in a general
router makes the rule unenforceable by inspection. Moved to a dedicated
`services/core/api/live_check.py`, which is now the single place the test needs
to allow.

### D-040 (GAP) Export row cap is deliberately not a scheme figure

The export paging limit collided textually with a RULE 4 scheme constant, and
the RULE 4 grep guard flagged it. Rather than teaching the guard an exception —
weakening it to accommodate an arbitrary paging number — the cap is
`MAX_EXPORT_ROWS = 20_000`. A guard with no exceptions stays trustworthy.

### D-041 (GAP) CSV carries a UTF-8 BOM; XLSX carries the compliance sheet

The officer's real tool is Excel on Windows, which renders Devanagari and Telugu
as mojibake without a BOM. The XLSX has three sheets — AAP annexure (counts by
GIA domain, the shape a plan needs), raw sessions for audit, and a compliance
sheet stating each mandate figure with its citation and whether the exported
population meets it, including how many rows are synthetic.

## Gate 10 — hardening

### D-042 (DEVIATION) A stopped database returned HTTP 500 with an empty body

Starlette's `@app.exception_handler(500)` does **not** fire for unhandled
exceptions — it handles explicitly raised 500 responses — so a dead database
produced a 500 with no body at all, which the PWA could only render as a blank
failure. The kill drill caught it. Handlers for `SQLAlchemyError` (→ 503 +
`Retry-After`) and `Exception` (→ 500) now return the standard error payload,
so the beneficiary hears a sentence in their own language and the client can
retry. `connect_args={"connect_timeout": 3}` bounds how long that takes.
Pinned by `test_gate10_hardening.py` so it cannot regress silently.

### D-043 (GAP) The embedder is warmed at startup

The first beneficiary turn after a cold boot loaded the sentence-transformer on
the request path: measured retrieval p95 of 11,268 ms against a 500 ms budget,
entirely the first call. A daemon thread started at boot encodes one query, so
the container still reports healthy immediately and the first real turn does not
pay the load. Measured after the change: retrieval p95 116.8 ms. Controlled by
`WARM_START` (default true).

### D-044 (GAP) Scoring is timed separately from retrieval

ARCHITECTURE §3 budgets "retrieval+scoring ≤0.5 s" as one line, and the API
timed the whole `recommend()` call as `retrieval`, leaving the `scoring` stage
declared in `metrics.STAGES` but never observed. STEP 4 now reports its own
span, so the report shows both halves of the budget instead of a stage that is
permanently empty.

### D-045 (GAP) The latency harness paces itself under the rate limiter

Driving journeys as fast as possible tripped `RATE_LIMIT_TURN_PER_MIN=30` and
11 of 12 journeys died on 429 — which would have produced a latency report drawn
from a single session. The harness now spaces turns under the limit and waits
out any 429 rather than counting the rejection as latency. Deliberately *not*
solved by adding a rate-limit bypass header: a documented way to disable the
limiter is a security defect that would outlive the benchmark.

### D-046 (GAP) What the retention purge keeps

ARCHITECTURE §11 says sessions are purgeable but not what happens to the rows
around them. Chosen: transcripts, recommendations and consents go with the
session (a consent record outliving what it consented to is a record of a person
with no justification for holding it); `audit_log` is kept, because it holds
officer actions rather than beneficiary speech and is what makes the deletion
itself demonstrable. The purge writes its own `retention_purge` audit row. A
dry run is the default — `--apply` is required to delete anything.
